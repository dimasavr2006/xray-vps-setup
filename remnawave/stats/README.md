# Интервальная статистика PDM

Статус 09.10.2026: SQL, read-only HTTP API и наблюдатель штатного сборщика
прошли проверки на отдельном Debian 13 и установлены в параллельном FI-контуре.
Интеграция backup/restore/upgrade/rollback проверена; это пилот.
Личные автоматические ограничения включаются
после проверки полноты и переноса исторической части.

`schema.sql` создаёт собственную схему `pdm_stats`. AFTER-триггер сохраняет
положительные приращения пользовательской истории. PostgreSQL UPSERT вызывает
только фактически применённое INSERT/UPDATE-событие; rollback отменяет и журнал.
Отрицательное изменение и повторное создание ряда открывают новую эпоху и
отмечают спорный интервал. Очистка истории панели не удаляет собственные события.
Ошибка дополнения оставляет штатную запись панели в силе и помечает неполноту.

Штатный сборщик не пишет строку для успешной пустой выборки. Наблюдатель
`panel-hook.cjs` оборачивает один метод закреплённого processor bundle и
записывает результат существующего `getUsersStats` вместе с ожидаемыми байтами.
Дополнительных запросов к Xray и сбросов счётчиков нет. Context изолирован
через AsyncLocalStorage. `patch-panel.cjs` принимает только исходный SHA256
`3c746587906be64386f673bb313a5813e4cab8283de1c847bf97187813fdb62e`
из официального образа Panel 3.4.5. При несовпадении изменение прекращается.

Дельты связываются с ожидаемыми штатными выборками FIFO. Их время — первое
поступление выборки, с точностью PostgreSQL microseconds. Задержанная запись
не переезжает через московскую границу месяца из-за очереди. Семантика — байты,
учтённые панелью, с её порогом `USER_USAGE_IGNORE_BELOW_BYTES`; время каждого
пакета не известно. `measured_until` показывает последний результат сборщика.
Нормальный период составлял 15 секунд в CI и 30 секунд на FI; разрыв более
90 секунд, ошибка выборки, непогашенные ожидаемые записи и спорные эпохи
делают соответствующую историю неполной.

Часы UTC уплотняются после 48 часов. Полный час берётся из корзины; частичный
интервал требует сохранённых сырых событий. Произвольный checkpoint защищает
весь свой час и не округляет саму границу. Уже уничтоженную детализацию
создание checkpoint задним числом не восстанавливает. Checkpoint неизменяем.

API обслуживает `GET /v1/users/ID/usage?start=ISO&end=ISO`, интервал `[start,end)`.
Ответ содержит байты по UUID нод, покрытые ноды, полноту, известный объём,
время наблюдения/выборки и состояние неизвестной части. При неполноте
`total_bytes=null`; `known_bytes` остаётся нижней подтверждённой величиной.
`unknown_bytes=0` при `unknown_bytes_are_quantified=false` не означает
подтверждённый нулевой пропущенный расход. До первой подтверждённой выборки
история неизвестна; существующие данные не становятся почасовыми задним числом.

HTTP API требует отдельный токен. Его PostgreSQL login может только вызвать
две read-only функции; он не читает таблицы панели и не может писать в
дополнение или подделывать выборки. Служба публикуется только на loopback,
использует 96 MiB, cap_drop ALL и read-only filesystem. На стенде потребляла
19 MiB в CI и около 22 MiB на FI. Бот получает HTTP API, а не доступ к PostgreSQL.

Установка из самодостаточного rwctl:

```bash
bash /opt/pdm-remnawave/ENV/rwctl stats install --stats-port 13100 --dry-run
bash /opt/pdm-remnawave/ENV/rwctl stats install --stats-port 13100
bash /opt/pdm-remnawave/ENV/rwctl stats status
```

Перед изменением создаётся согласованный backup. При отказе активации прежний
стек восстанавливается. Restore создаёт read-only роль до pg_restore и заново
генерирует доверенный код addon; исполняемый код из архива не запускается.
Проверены purge/restore, upgrade/rollback и конфликт порта с возвратом прежнего
стека. С изменением digest панели addon требует новой проверки совместимости.
В compact-test общий лимит со статистикой — 1248 MiB, heap панели 160 MiB
при прежнем hard limit 512 MiB. История до первой подтверждённой выборки неизвестна.

Проверки: [verification.stats.json](../tests/verification.stats.json) и
[stats-live.py](../tests/stats-live.py). FI: установка 09.10.2026 01:09 UTC,
loopback 13100, штатные выборки подтверждены. Основная панель, бот,
агенты квот и рабочие аккаунты не переключались.
